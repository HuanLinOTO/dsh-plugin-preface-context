# @huanlin/dsh-plugin-preface-context · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 上游对照：tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be)，234 commits。
> 证据均为只读命令产出（`git -C D:/Projects/deepseek-harness/dsh show/diff/grep <tag>`），未修改 dsh/ 任何文件。

## 结论

**⚠️ 需适配 —— 一处两行代码改动 + 重建 `lib/`。**

alpha2 把 `@deepseek-ai/dsh-settings` 的 `settingsNamespace()` 品牌构造函数**删除**了（ replaced 为普通字符串 + 类型层校验）。本插件 host 半部 `src/settings.ts` 是该 API 的消费者，且已构建的 `lib/index.js:2` 含 `import { settingsNamespace } from "@deepseek-ai/dsh-settings"` —— **不改造直接升 alpha2，host 半部加载即抛 `does not provide an export named 'settingsNamespace'`，整个插件失效**。除此之外，插件用到的其余全部 dsh 面（agent 事件/inject、llm 消息源、ui-slots 契约、`settings.plugin.item` 槽、SettingsScope 客户端契约、ui-primitives 图标、locale、invariants、client-store）经逐一比对 alpha2 源码**全部未变**，peer 依赖 semver 也仍然满足。

## 迁移步骤

1. **前置（dsh 侧，人工执行）**：按 AGENTS.md 的《更新 DSH 源码 checkout》SOP 把 `~/.dsh/source/current` 升到 `dsh-v0.1.2-alpha.2`（`git pull --ff-only` → `pnpm install --prefer-offline` → `pnpm run build`，前台长 timeout）。插件 `typecheck` 的 tsconfig paths 直接解析该树的 `lib/types`，这步没做插件三件套必挂。
2. **唯一必改的代码**（`src/settings.ts`）：
   - 删除第 22 行 `import { settingsNamespace } from '@deepseek-ai/dsh-settings'`（保留第 23 行 `import type { SettingsScope }`，该类型 alpha2 仍导出）；
   - 第 28 行改为字面量：
     ```ts
     export const PREFACE_SETTINGS_NAMESPACE = 'preface-context'
     ```
     alpha2 的 `register` 接受匹配 `/^[a-z][a-z0-9-]*$/` 的普通字符串（类型级由 `SettingsNamespaceInput<'preface-context'>` 放行，运行时 `parseSettingsNamespace` 再验一次），`'preface-context'` 合法。客户端半部的 `SETTINGS_NAMESPACE`（`src/client/index.ts:47`）本来就是普通字符串，无需动。
   - （可选）顺手更新 `src/settings.ts:59` 注释里对上游 `installSettingsSection` 的引用（alpha2 已删该导出）。
3. **无需改动**（已逐一核对 alpha2 源码）：`src/index.ts`、`src/config.ts`、`src/invariant.ts`、`src/client/*` 全部文件、`tests/*`、`cordis.patch.yml`、`package.json` 的 `dsh.bundle.patch` / `dsh.client.inject` / `files` / scripts、`tsconfig*.json` 的 paths（alpha2 中所有被映射包的路径原位存在）。
4. **重建与测试**（workdir=插件目录）：
   ```powershell
   pnpm run typecheck   # 此时类型解析已指向 alpha2 lib/types，settingsNamespace 报错应消失
   pnpm test            # vitest run（42 用例；tests/support/memory-settings.ts 的类型 import 仍有效）
   pnpm run build       # 重建 lib/index.js / lib/invariant.js / lib/client.js + lib/types
   ```
   `package.json` 无 `link:`/`overrides`、无 `prepare`，无需其他安装动作。
5. **profile 端验证**：本机 profile 是 `link:` 引用 → 重建 `lib/` 后 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-preface-context/lib/` 即时可见，**无需** `dsh plugin add/update`。对外发布按 huanlinoto SOP：`pnpm run build` → `git add lib/` → commit → push（`github:` 引用方再 `dsh plugin --profile web update @huanlin/dsh-plugin-preface-context`；npm 分发可选 `pnpm publish`）。
6. **收尾**：重启 `dsh web` 进程 + 浏览器硬刷新（`Ctrl+Shift+R`，client.js 走模块表加载，普通刷新不够）。

## 升级后验证清单

> 全部在 `dsh web` **重启 + Ctrl+Shift+R 之后**进行。

1. **加载无错**：DevTools Console 无 `does not provide an export named 'settingsNamespace'`、无 `missed the module table`、无 `Cannot find package`（升级前旧 lib/ 恰好会报第一条，可反向确认新产物已生效）。

3. **写入链路**：拨动「启用」开关、在 textarea 输入多行文本 → 未保存徽标出现 → 保存 → 徽标消失且无 saveFailed；硬刷新后值仍在（settings-file 持久化生效）。
4. **覆盖/恢复语义**：保存后字段出现「已覆盖」badge；点「恢复默认」→ 字段回到 composition base（badge 消失）。
5. **注入链路**：新建会话，确认首条 `user/message`（source `plugin/instructions`）携带所配文本进入 transcript（模型首答应能引用该上下文）；关闭开关或清空文本后新会话不注入。
6. **live 生效**：改文本并保存后**不重启**，直接再开一个新会话 → 新文本即生效（验证 `installPrefaceSettings` 的 live source 桥在 alpha2 的 settings 注册语义下仍工作）。
7. **回归**：`pnpm test` 全绿（settings bridge 的 entry-source fallback / multi-fiber 去重路径尤其覆盖 alpha2 的 `already registered` 行为）。
